GeoReady: where can solar connect in the Northern Cape?Preview

A reproducible screening model that goes past site suitability to investment readiness: eligible land, capacity, indicative cost, grid headroom and permitting, zone by zone. Built as Jupyter notebooks that also run inside QGIS.

  • Utility-scale solar PV · Northern Cape pilot
  • Grid limits from NTCSA GCCA 2025
  • Five notebooks · run 2026-11-26_nc-pv-v01_3d5fc633

Explore the model

Zones are 10 km squares of eligible land, split by GCCA substation zone. Coloured land inside a square is excluded; the outlined zones get capacity in the chosen scenario.

Why this zone

Key takeaways

  • Land is not the constraint. About 184,000 km², half the province, passes every exclusion. Built out at a tenth of that land, the 2,132 zones hold about 1,560 GW.
  • The grid is. Under GCCA 2025 as published, every zone sits behind a local-area or supply-area limit of 0 MW. Nothing can connect.
  • If the backbone were reinforced, substation limits alone would allow about 4.3 GW, in 18 zones. Eight substations, with 45% of the technical potential behind them, report 0 MW even at the substation.
  • Cost barely separates zones: 90% fall between R807 and R886/MWh in the base case. Grid headroom separates them.

Method

Each 250 m cell gets an exclusion reason: protected areas (a legal bar), then land cover, slope over 15°, weak sun, or more than 50 km from a ≥132 kV substation (editable thresholds). Eligible land is cut into zones; capacity, yield and cost follow; GCCA limits are shared, so capacity is allocated cheapest-first and never counted twice.

Readiness weighs sun (0.20), cost (0.25), distance to grid (0.15), grid headroom (0.25) and REDZ (0.15) on fixed scales.

Data and tools

  • Data: Global Solar Atlas, Copernicus DEM, SANLC 2022, WDPA, DFFE/CSIR REDZ and EIA applications, NTCSA GCCA 2025, OpenStreetMap
  • Tools: Python (NumPy, pandas, GeoPandas, rasterio), Jupyter, QGIS and the QGIS Notebook plugin, pytest, MapLibre GL

How the model runs

Five notebooks on a small Python package, each writing into one run folder. Every assumption sits in a YAML file with its source; every input is checksummed; and the last notebook writes nothing unless the release gate passes. The same notebooks run in plain Jupyter and inside QGIS, where the final cell loads the results onto the map.

  • 00_run_record.ipynb · Run record: parameters, input checksums, software
  • 01_eligibility_zones.ipynb · Exclusion reasons and candidate zones
  • 02_capacity_cost.ipynb · Capacity, yield, connection cost and LCOE
  • 03_grid_readiness.ipynb · GCCA limits, allocation, supply curves, readiness, sensitivity
  • 04_qa_publish.ipynb · QA gate, outputs, and the QGIS hook

Is the cost believable?

The levelised cost uses sourced assumptions in real 2025 rand: plant CAPEX anchored on IRENA's 2024 cost data, Eskom's line and substation building blocks for connection, and the IRP's 8.2% real discount rate. The low case lands near the prices REIPPPP Bid Window 7 solar projects bid (R500–514/MWh, median R537 here). The base case is higher (median R847), because it assumes fixed panels, where new plants track the sun, and cautious CAPEX. Read the cost axis as relative: which zones are cheaper is more robust than the rand level.

Release gate for this run

The checks from the GeoHub implementation guide, run by notebook 04 before any output is written.

  • Mandatory exclusions (grid) 0 eligible cells touch protected areas
  • Mandatory exclusions overlap 0.0000 km² (tolerance 0.01)
  • Grid allocation (published) all limits respected
  • Grid allocation (strengthened) all limits respected
  • Grid allocation (unconstrained) all limits respected
  • Unknown grid explicit 0 zones behind unknown headroom
  • Units and totals max difference 5.68e-14 MW
  • Readiness weights sum 1.000
  • Unit tests 59 passed in 1.00s

What this is not, and its limits

  • A screening, not a permit or a feasibility study. A readiness score is not an environmental authorisation, land entitlement, engineering design or bankable study.
  • Grid headroom is a dated public assessment. GCCA 2025 limits are indicative, not connection offers. They are shared with projects outside the province, which are not modelled, so every allocation is an upper bound. Upstream limits beyond the supply area are not captured.
  • Distances are straight lines to the nearest ≥132 kV substation in OpenStreetMap, scaled by a route factor; real routes are longer and substations may be missing.
  • Thresholds are choices. The 50 km cap, the 15° slope limit and the 10% land-use factor are editable in the config; only protected areas are treated as a legal bar. How the province's land splits, by reason:
    • Eligible: 183,874 km² (49%)
    • Protected area (legal): 20,488 km² (5%)
    • Incompatible land cover: 6,688 km² (2%)
    • Too steep: 6,110 km² (2%)
    • Weak solar resource: 4,827 km² (1%)
    • Too far from a substation: 150,906 km² (40%)
  • Not yet reviewed. The cost and capacity assumptions still need review by a renewable-energy engineer and a grid planner, as the implementation guide asks. This page is a preview.
